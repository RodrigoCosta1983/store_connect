4. FALHA HISTÓRICA R2 — CAUSA E IMPLICAÇÕES

Teste original: test/checkout_sdk_bundle_web_test.dart:126–141.
Histórico preservado: esperado null, observado CheckoutContextBinding; R2 8/9,
uma falha obrigatória, exit 1. O log histórico foi lido e confirma Expected/Actual.
Teste, expectativa, helpers e logs antigos não foram editados ou enfraquecidos.

Cadeia causal observada no código:
1) instanceFor usa cache pela chave app.name/região e devolve o mesmo objeto.
2) Outro módulo recupera esse objeto e muda _origin para 127.0.0.1:5002.
3) O setter não modifica app/opções, tenant Auth, database Firestore, UID,
   geração Auth ou conjunto/nome de Firebase.apps.
4) _coherent do protótipo verifica esses campos e a origem da página Web.
   O campo _origin do BUNDLE guarda origem da página; não é o _origin privado
   de FirebaseFunctions. Ele não observa a nova configuração de Functions.
5) capture mantém o binding porque _coherent, UID e geração ainda coincidem.

O teste histórico não invoca callable e não mede tráfego para 5002. Ele demonstra
que o receipt imutável e as observações usadas pelo protótipo não detectam a
configuração divergente que orientaria chamadas. A aplicação Web de origin no
serviço JS ocorre em call/stream, não nesse simples setter Dart.
Não se atribui essa falha à divergência de versão JS: a causa de observabilidade
e ownership é separada de K16.

URL explícita: no caminho examinado, httpsCallableFromURL entrega a URL recebida
a callAtURL; não a deriva por _url(name)/emulatorOrigin. Isso sustenta controle
do endereço inicial pelo código confiável que constrói a literal permitida.
O ensaio real HISTÓRICO R2 de URL explícita já observou esse roteamento; não foi
reexecutado nem ampliado para certificar a nova implementação.

Limites: URL explícita não congela provider Auth/App Check, credenciais, sessão,
registros globais, serviço JS recuperável, política de redirects ou runtime.
O postJSON ESM examinado não configura redirect:error. Não inferir ausência de
redirect por passar uma URL fixa. Headers são obtidos de forma assíncrona.
callAtURL aguarda headers e só depois disputa postJSON com cancelAllRequests;
por essa ordem, _delete não demonstra ausência de envio após delete durante
aquele await. É inferência estática delimitada, NÃO teste de corrida.
Captura de token Auth pode falhar e o código JS pode prosseguir sem esse header;
autorização real continua exigindo contexto e validação do servidor.

Conclusão limitada: recusar pedidos controlados de reconfiguração e fixar URL
no código revisado são propriedades possíveis. Detectar toda mutação externa
oculta usando o receipt e as observações atuais não foi demonstrado, nem é
garantido pelo validador puro entregue. Não existe lock público de ownership
demonstrado para congelar esses caches/configurações. Sob K14, código arbitrário
no mesmo processo está fora da promessa; mistura acidental continua defeito.

WeakMap local reconhece apenas planos emitidos pela própria fixture; cópia,
serialização, objeto externo ou plano de outra fixture são recusados.
Um descritor de perfil/origin/destino divergente, pedido controlado de
reconfiguração ou retire torna o plano observado obsoleto, sem reset.
Campos extras, getters e entrada ilegível falham fechados. Comparação da URL é
literal: rejeita aliases, query/fragment, userinfo, normalização e paths comerciais.

Há controle positivo de correspondência local, para não testar apenas um
validador que sempre retorna false. Mesmo nesse controle: runtimeAuthorization
permanece false e sdkAdmission BLOCKED. O plano não é CheckoutContextBinding,
não autentica FirebaseApp ou usuário e não é receipt de admissão do SDK.

Não existe send/call/capture/sdk/configure/httpsCallable nessa API. Nenhum SDK
é simulado para declarar isolamento. A identidade é da fixture de validação;
ausência de identidade SDK nunca permite autorização de runtime.
Mudança oculta com os mesmos descritores é indistinguível para esse código,
e o teste explicita o limite. Reprovação R2 não está corrigida nem substituída.
retire trata apenas o plano local: sem listeners, sessão Auth, geração, fan-out
ou autoridade B4-C. Não foi reimplementado o owner inerte R4-A.

review-functions.cjs exporta apenas essa revisão Functions, reaproveitando
